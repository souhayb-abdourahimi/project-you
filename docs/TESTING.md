# Tests

| Niveau | Outil | Commande | Contenu |
|---|---|---|---|
| Unitaires | Jest (jest-expo) | `npm test` | moteurs du domaine, i18n (parité FR/EN), contraste des tokens, providers, sync |
| Base de données | psql + Postgres 16 | `npm run test:db` | migrations ; audit RLS de **toutes** les tables à `user_id` (A/B, anon, politiques) ; cascade de suppression ; synchronisation réelle contre le schéma (`sync.db.test.ts`) |
| Supabase réel | Jest + supabase-js (clé publishable) | `npm run test:live` | inscription/connexion, mauvais mot de passe, restauration et rafraîchissement de session, anon, sync complète, isolation A/B, déconnexion. Nécessite deux comptes de test confirmés (`SUPABASE_TEST_EMAIL_A/B`, `SUPABASE_TEST_PASSWORD_A/B` en variables d'environnement ou dans `.env.local`) et l'accès réseau au projet. Tourne dans Node pur (`jest.live.config.js`), sans le preset jest-expo dont le `fetch` ne fonctionne pas hors app. Connexion validée manuellement (curl) le 2026-10-01 ; suite automatique à relancer depuis un poste qui atteint le projet. |
| Santé (simulée) | Jest | `npx jest src/domain/health src/providers/__tests__/health.test.ts` | moteur santé (unités, validation, dédoublonnage, fusion avec les pesées et séances Project You, tendance des pas, refus, révocation, aucune donnée, échec de lecture) ; providers iOS/Android contre des modules natifs **simulés** (`jest.setup.js`). Aucun test sur appareil réel : voir `docs/MOBILE_HEALTH_TEST_PLAN.md`. |
| Données Ciqual | Jest + script Python | `npx jest src/domain/meals/ciqual` · `npm run ciqual:check` | empreinte SHA-256 du fichier source ; conventions des cellules (virgule, « - », « traces », « < x ») et texte brut conservé ; unités (g ou kcal pour 100 g) ; cohérence énergie / macronutriments (facteurs UE, tolérance 6 %) ; correspondance unique aliment → code ; catalogue identique aux valeurs Ciqual, rien de MOCK ; recettes recalculées indépendamment ; valeurs de référence (non-régression). Contraintes vegan, allergies, petit budget et cible de protéines retestées avec les valeurs réelles (`meals/__tests__`). Le script vérifie que le fichier généré correspond exactement à la source (CI). |
| Exclusions et diagnostic (D-021) | Jest + Playwright | `npx jest src/domain/meals/__tests__/exclusions.test.ts src/domain/meals/__tests__/diagnosis.test.ts` | normalisation (casse, accents, œ, pluriels) ; « soja », « poisson », « viande », « oeufs », « arachide », « noix », « fruits à coque », « pomme » ≠ « pomme de terre » ; intolérances ; plans de la semaine sans aliment exclu ; végan + soja expliqué ; chaque ajustement proposé vérifié ; 72 combinaisons de contraintes sans repas manquant inexpliqué. E2E : « Ce que l'application a compris » et carte « Ton plan de repas est incomplet ». |
| Journées incomplètes (D-022) | Jest + Playwright | `npx jest src/domain/meals/__tests__/energy.test.ts` | calcul du manque et du plancher ; redistribution (végan + soja : petit-déjeuner absorbé) ; avertissement quand elle ne suffit pas (végane 50 kg, soja, 10 min : 550 kcal) ; homme et femme de 50 kg ; remplacement d'un repas ; 162 combinaisons sans journée basse silencieuse. E2E : message sur Nutrition et Aujourd'hui, absence de message quand la redistribution suffit. |
| Build | Expo | `npm run build:web` | export web de production |
| E2E | Playwright (web, Chromium) | `npm run build:web && npm run test:e2e` | sur l'export web en mode local, viewports mobile (Pixel 7) et desktop (1366×900) : parcours complet onboarding → objectif → repas → inventaire → séance 15 min → pesée → bilan hebdo → suppression Privacy Center ; navigation par onglets ; contraintes dures (vegan, allergies multiples) vérifiées contre le catalogue ; aucun prix inventé (petit budget) ; exercices compatibles sans salle ; emploi du temps chargé ; « Pas envie » ; santé sur le web (message « non disponible », saisie manuelle, section du Centre de confidentialité). Chromium préinstallé : `PW_CHROMIUM_PATH=/chemin/chrome`. Le parcours avec compte Supabase n'est pas couvert (réseau). |

CI : `.github/workflows/ci.yml` (lint, typecheck, tests, contrôle de l'extrait Ciqual, build web, tests DB sur service Postgres, E2E).

Scénarios MOCK partagés : `src/domain/scenarios` (étudiant budget faible/moyen, prise de masse, perte de gras, recomposition, débutant, avancé, sans salle, vegan, emploi du temps chargé). Scénarios « voyage » et « hors connexion » à ajouter avec la sync (M-19).

Priorités : onboarding, nutrition, progression, workout, RLS, sync, IA structurée. Un bug corrigé commence par un test qui échoue.
